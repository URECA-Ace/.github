본 시스템은 **대규모 트래픽 환경에서 선착순 쿠폰 발급 시 발생하는 동시성 문제와 데이터 정합성을 안정적으로 처리하는 것**을 목표로 설계했습니다.

사용자의 쿠폰 발급 요청은 **Nginx**를 통해 전달되며, **Redis에서 재고 차감과 중복 발급 여부를 빠르게 검증**합니다. 발급에 성공한 요청은 이후 **Kafka 이벤트 스트림**을 통해 비동기적으로 전달되고, Consumer가 이를 **MySQL에 최종 발급 이력으로 저장**합니다.

또한 **Prometheus + Grafana**를 활용하여 TPS, 응답 시간, Redis/Kafka 상태 등을 모니터링하고, 별도의 정합성 검증 Runner를 통해 Redis와 MySQL의 데이터가 일치하는지 검증합니다.

## 🔧 기술 선택 이유

| 기술 | 선택 이유 |
|---|---|
| **Redis** | 대규모 동시 요청에서 DB에 직접 접근하지 않고 재고 차감과 중복 발급 검증을 빠르게 처리하기 위해 사용 |
| **Kafka** | 쿠폰 발급 처리와 DB 저장을 분리하여 대량의 이벤트를 안정적으로 처리하고 비동기 구조를 구성하기 위해 사용 |
| **MySQL** | 쿠폰 발급 이력과 사용자 데이터를 영구적으로 저장하고, Unique 제약 등을 통해 최종적인 데이터 정합성을 보장 |
| **Nginx** | 대량의 요청을 안정적으로 받아 백엔드로 전달하고 트래픽을 분산 |
| **JMeter** | 대규모 동시 요청을 재현하여 쿠폰 발급 시스템의 성능과 동시성 제어를 검증 |
| **Prometheus + Grafana** | TPS, 응답 시간, Redis/Kafka 상태 등을 모니터링하여 병목 구간과 시스템 상태를 확인 |
| **Docker Compose** | Redis, Kafka, MySQL, 모니터링 환경 등을 동일한 환경에서 구성하고 쉽게 재현하기 위해 사용 |

## 🚀 단계적인 개선 방식

처음부터 Redis, Kafka 등 모든 기술을 적용하는 것이 아니라, **단계적으로 구현하고 부하 테스트를 수행하면서 시스템을 개선**하는 방식으로 진행합니다.

### 1️⃣ Redis 기반 초기 구현

먼저 **Redis만 사용하여 선착순 쿠폰 발급 기능을 구현**합니다.

- Redis Lua Script를 이용한 원자적 재고 차감
- 중복 발급 방지
- 재고 부족 여부 검증
- 발급 가능 시간 검증

이후 **JMeter를 이용해 대규모 동시 요청을 발생**시키고 Redis 기반 동시성 제어가 정상적으로 동작하는지 확인합니다.

### 2️⃣ 부하 테스트 및 문제점 분석

Redis 기반 구현의 테스트 결과를 바탕으로 다음 항목을 확인합니다.

- TPS
- 평균 및 최대 응답 시간
- 동시 요청 처리량
- 재고 초과 발급 여부
- 중복 발급 여부
- DB 부하
- Redis 처리 한계 및 병목 구간

테스트를 통해 실제 병목 지점을 파악한 후 다음 단계의 기술 도입 여부를 결정합니다.

### 3️⃣ Kafka 도입

Redis만으로 처리하기 어려운 **DB 저장 부하와 비동기 처리 문제**가 확인되면 Kafka를 도입합니다.

```text
Client
  ↓
Nginx
  ↓
쿠폰 발급 API
  ↓
Redis
  ↓
발급 성공
  ↓
Kafka
  ↓
Consumer
  ↓
MySQL
```
